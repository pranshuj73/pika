CPSR: the CPU's status line — and Go bit ops that make it real

Your README literally says "cpsr (wtf is cpsr?)". This lesson kills that TODO. It also teaches the Go idiom (&^=, masks, typed constants) you'll use in every instruction you ever implement. One stone, both birds.

The idea in one paragraph

The ARM7TDMI (the GBA's CPU) has 16 registers, r0–r15 (cheat sheet). Fifteen hold data. But the CPU also carries status: did the last result come out negative? zero? was there a carry? which mode am I in? ARM packs all of that into one extra 32-bit word called the CPSR — Current Program Status Register (GBATEK). You already modelled it: type CPSR uint32. Every bit is a flag; you manipulate it with bitwise ops. That's the whole mystery.

Bit layout (the part worth memorizing)

 31 30 29 28  27   7  6  5  4-0
 ┌──────────────┬───┬────────┬──────┐
 │ N  Z  C  V   │ Q │ I F T  │ mode │
 └──────────────┴───┴────────┴──────┘
   condition      rsv IRQ FIQ THUMB
  • N Z C V (top 4 bits): condition flags. Set by arithmetic; read by conditional instructions like BEQ. This is why ARM has no jump if equal opcode — it has B + a 4-bit condition checked against the CPSR.
  • I, F: disable IRQ/FIQ interrupts.
  • T: THUMB state toggle. BX to an odd address sets T=1 and switches the CPU to 16-bit instructions. Your InstructionState enum and this bit must always agree.
  • mode (low 5 bits): 0x10 User, 0x12 IRQ, 0x13 Supervisor, 0x1F System… (full table). Mode switches swap in banked copies of r13/r14 — that's for a later lesson; today just decode it.

Go's bit-manipulation toolkit

Emulator code is 50% bit twiddling. These are the five idioms — all already idiomatic Go, no imports:

const (
    flagN uint32 = 1 << 31
    flagT uint32 = 1 << 5
    modeMask    = 0x1F // low 5 bits
)

func (c CPSR) Has(f uint32) bool { return c&f != 0 }
func (c *CPSR) Set(f uint32)     { *c |= f }
func (c *CPSR) Clear(f uint32)   { *c &^= f }  // &^ is Go's "AND NOT" bit-clear
func (c CPSR) Mode() uint8       { return uint8(c & modeMask) }

Notes: &^ has no C equivalent — it's a & ^b as one operator. Notice Has takes a value receiver (read-only) while Set/Clear take pointer receivers — they mutate. That receiver choice is a core Go decision you'll make thousands of times in this project.
